# 개인 PC 모드 (Personal mode) 사용 안내

내 PC에 이미 있는 문서로 **나만의 LLM 위키**를 만들고 자연어로 질문하는 모드다. 사내 중앙 위키(`docs/ONSITE-HANDOFF.md`)와 같은 엔진을 쓰지만 **별개 프로그램**이다.
표기: **[검증]** = 개발 PC에서 테스트/실행으로 확인, **[미검증]** = 이 PC(실사용 PC)에서는 아직 실행해 보지 않음.

## 1. 무엇이고 무엇이 아닌가
- 맞다: 사용자 1명(나), 공간 1개(`personal`), 데이터는 이 PC에만 저장. 질문하면 내 문서만 근거로 출처를 달아 답한다. [검증]
- 아니다: **중앙 위키의 동기화/복제가 아니다.** 중앙 위키 내용을 가져오지 않고, 내 위키를 중앙으로 올리지도 않는다. 공유 기능 없음.
- 팀과 공유하려면: 해당 파일을 **직접** 부서 공유 폴더(inbox)에 넣는다. 개인 위키 안의 문서가 자동으로 공유되지는 않는다.
- 중앙 서버(`python -m llmwiki.web`)는 개인 모드를 거부한다 (`WIKI_MODE=personal`, `WIKI_AUTH_PROVIDER=personal`). [검증]

## 2. 준비물
- Python 3.14 (저장소의 `.venv` 사용: `scripts\setup-venv.ps1`). 내부 미러에서 `pip install` 가능해야 한다. PDF 는 `pip install pypdf` 필요.
- 채팅 모델 — 둘 중 하나:
  - **A. LM Studio(이 PC의 GPU)**: 채팅 모델 1개 + 임베딩 모델 `bge-m3` 로드, Local Server 켜기(포트 1234), Context Length 8192 이상.
  - **B. 사내 Gauss Chat API**: Bearer 키 파일 필요. 이 경우에도 **임베딩은 이 PC의 LM Studio(bge-m3)** 를 쓴다.
- 환경 파일: `config\env.personal.example` 을 repo 루트에 `.env.personal` 로 복사해 고친다. 프로필 A/B 설명이 들어 있다. `.env.personal` 은 `.gitignore` 에 포함되어 커밋되지 않는다(그래도 키 값은 쓰지 말고 `*_FILE` 경로만 쓴다).

## 3. 설치와 실행
1. `copy config\env.personal.example .env.personal` 후 모델 주소/컨텍스트(`WIKI_LLM_CONTEXT_TOKENS`)를 맞춘다. 키는 `WIKI_LLM_API_KEY_FILE` 로 파일 경로만 적는다.
2. 점검: `scripts\run-personal.ps1 -Check` (또는 `python -m llmwiki.personal --check`). LLM/임베딩 연결, 컨텍스트 설정, 쓰기 가능 여부, 루프백 바인드, 감시 폴더를 PASS/WARN/FAIL 로 보여 준다. FAIL 이 있으면 종료 코드 1. 키 값은 출력되지 않는다. [검증: 가짜 모델 서버로 확인 / 실제 LM Studio·Gauss 는 미검증]
3. 실행: `scripts\run-personal.cmd` (또는 `.ps1`). 콘솔에 `http://127.0.0.1:<포트>/?token=...` 주소가 나오고 브라우저가 열린다. `--no-browser` 로 자동 열기를 끌 수 있다. 종료는 Ctrl+C.
4. 이 주소의 토큰은 **실행할 때마다 새로 만들어지고 딱 한 번만 쓸 수 있다**(첫 `GET /` 교환 후 401, 주소는 다시 표시되지 않음). 남에게 보내지 말 것. 브라우저가 열리지 않았거나 세션이 만료되면(최대 24시간) **프로그램을 재시작**해 새 주소를 받는다. 세션 쿠키 이름은 포트별(`wiki_sid_<포트>`)이라 여러 개를 띄워도 섞이지 않는다.
5. 포트를 고정(`--port N`)해도 다른 프로그램이 같은 포트를 가로채지 못하도록 독점 바인드(SO_EXCLUSIVEADDRUSE)를 쓴다. 이미 쓰는 포트면 시작이 거부된다. [검증: Windows 개발 PC]

## 4. 폴더와 자료 넣는 법
데이터 위치: `%LOCALAPPDATA%\LLMWiki` (`WIKI_PERSONAL_HOME` 으로 변경). 이 밖에는 쓰지 않는다(감시 폴더는 읽기만).
- `inbox\` — 여기에 파일을 넣으면 처리된다(하위 폴더도 됨, 모두 공간 `personal`). 성공하면 `inbox\_done\personal\`, 실패는 `_failed`, 지원하지 않는 형식은 `_rejected` 로 이동한다. 브라우저 '업로드' 탭도 같은 곳에 저장한다.
- `wiki\` — 옵시디언 호환 마크다운 위키. 옵시디언에서 이 폴더를 보관소로 열면 된다. `raw\` 는 정규화된 원문 사본, `wiki.db` 는 색인/감사 기록.
- 지원 형식: `.md .txt .docx .xlsx .eml .pdf` (스캔 PDF 는 OCR 설정 없으면 실패).
- **감시 폴더(선택)**: `WIKI_PERSONAL_WATCH=C:\Users\me\Documents\회의록;D:\문서` 또는 `<home>\settings.json` 의 `{"watch": ["C:\\..."]}`.
  - 하위 폴더까지 주기적으로(약 1분) 훑어 **새 파일/바뀐 파일만 복사**해서 처리한다. 원본은 읽기만 하고 **이동·이름 변경·수정·삭제를 하지 않는다**(마스킹을 켜도 동일). [검증]
  - 무시: `~$*`, `Thumbs.db`, `desktop.ini`, `*.tmp`, 숨김/시스템 속성 파일, 바로가기/심볼릭 링크/정션(따라가지 않음), 크기 상한(기본 50MB) 초과, 데이터 폴더 안의 모든 것.
  - 원본을 **삭제해도 위키 내용은 지워지지 않는다.** 원본을 수정하면 새 버전이 추가로 처리된다(기존 문서를 덮어쓰지 않음).
- 화면 상단에 `개인 위키 · 처리 대기 N건 / 실패 N건` 이 표시된다(개수만, 파일 이름 없음). '설정' 탭에 데이터/감시 폴더 경로가 보인다.

## 5. 개인정보와 삭제
- 원본은 건드리지 않는다. 저장되는 `raw`/`wiki` 사본에만 `WIKI_MASK_PII=1` 마스킹이 적용된다 — **원본 파일은 마스킹 없이 디스크에 그대로 있다.** [검증]
- 데이터는 `%LOCALAPPDATA%\LLMWiki` 에만 있다. 본인 계정 폴더이지만 **BitLocker 등 디스크 암호화를 권장**한다. [미검증: 암호화 상태는 이 PC에서 확인하지 않음]
- 모델 호출은 설정한 채팅/임베딩 주소로만 나간다. 텔레메트리 없음. Gauss(B) 사용 시 질문과 문서 일부가 사내 API 로 전송된다.
- 데이터 폴더를 `D:\MyWiki` 처럼 **사용자 프로필 밖**에 두면 드라이브 루트의 넓은 권한을 상속할 수 있다. `--check` 가 경고(WARN)하며, 본인만 접근하게 하려면 `icacls "D:\MyWiki" /inheritance:r /grant:r "%USERNAME%:(OI)(CI)F"` [미검증, 자동 실행하지 않음]. 기본 위치(`%LOCALAPPDATA%`)를 권장한다.
- 전부 삭제: 프로그램 종료 후 `%LOCALAPPDATA%\LLMWiki` 폴더를 삭제한다(위키, 원문 사본, 색인, 감사 기록이 모두 사라짐). 원본 문서는 영향 없음. 처리 후 `inbox\_done` 의 사본만 지워도 된다.

## 6. 한계
- 속도: 저자 PC(GPU 5GB, 4B 모델)에서 문서 1건 처리 35~47초. **CPU 전용 PC는 훨씬 느릴 것이며 측정하지 않았다.** [미검증]
- LM Studio 는 요청을 한 번에 하나만 처리한다. 그래서 프로그램 안에서 모든 모델 호출을 한 줄로 세우고 **질문이 문서 처리보다 먼저** 실행되게 한다. 일시적 오류(연결 끊김, 타임아웃, 5xx, 컨텍스트 초과가 아닌 400)는 2초/5초 간격으로 최대 3회 재시도한다. 컨텍스트 초과와 401/403 은 재시도하지 않는다. [검증: 가짜 클라이언트]
- 문서 처리 중에는 답변이 늦어질 수 있다(화면에 안내). 질문이 `WIKI_PERSONAL_QUESTION_WAIT`(기본 300초) 넘게 기다리면 "문서 처리 중이라 답변이 지연됩니다. 잠시 후 다시 시도하세요" 를 보여 준다. 동시 사용자 1명 전제. [검증: 가짜 클라이언트]
- 재시도: 연결 오류/타임아웃/5xx/429 는 최대 3회, 컨텍스트 초과가 아닌 400 은 1회만 재시도한다.
- 감시 폴더에서 Windows 예약 이름(`nul`, `con`, `com1` ...)이거나 경로가 너무 길어 복사할 수 없는 파일은 건너뛰고(`skipped_unstageable`) 크기/수정시각이 바뀔 때까지 다시 시도하지 않는다. 복사 중 원본이 바뀌거나 링크로 바뀌면 그 복사본을 버린다.

## 7. 보안 메모 (이 PC 안에서의 위협 모델)
- 서버는 `127.0.0.1`(또는 `::1`)에만 바인드한다. `WIKI_HOST=0.0.0.0` 은 무시된다. 모든 요청은 접속자가 루프백이고 `Host` 가 `127.0.0.1:<포트>`/`localhost:<포트>`/`[::1]:<포트>` 일 때만 처리한다(DNS 리바인딩 방어). [검증]
- 접속 열쇠(토큰, 192비트)는 메모리에만 있고 디스크/로그에 남지 않는다. 열쇠 없는 요청은 401, 열쇠를 낸 첫 요청은 세션 쿠키(HttpOnly, SameSite=Strict)를 받고 열쇠 없는 주소로 이동한다. CSRF 토큰과 Origin 검사도 유지된다. [검증]
- 남는 위험: **같은 PC의 같은 Windows 계정에서 도는 다른 프로그램**은 콘솔/브라우저 기록의 주소를 알면 접속할 수 있다. 같은 PC의 다른 Windows 사용자는 열쇠가 없어 접속할 수 없지만, 파일 권한이 느슨하면 `%LOCALAPPDATA%` 데이터를 읽을 수 있다. [미검증: 다중 사용자 PC에서 확인하지 않음]
- 브라우저 확장/원격 데스크톱/화면 공유 중에는 화면에 문서 내용이 보인다.

## 8. 문제 해결
- 화면에 `{"error":"unauthorized"}`: 열쇠 없이 접속했다. 콘솔에 표시된 `?token=` 주소로 접속한다.
- `403 forbidden`: 주소를 `http://127.0.0.1:<포트>/` 가 아닌 다른 이름/IP/포트로 열었다.
- `startup refused`: 환경 파일 값 오류(감시 폴더가 상대 경로, OCR 설정 오류 등). 메시지대로 고친다.
- 질문하면 "답변 서버에 연결할 수 없습니다": `-Check` 로 확인. LM Studio Local Server 가 켜져 있고 모델이 로드됐는지, 포트가 1234 인지 본다.
- 문서가 `_failed` 로 갔다: 컨텍스트 초과면 `WIKI_LLM_CONTEXT_TOKENS` 와 LM Studio Context Length 를 맞추고 `WIKI_COMPILE_MAX_CHARS` 를 줄인다. 파일을 다시 `inbox` 에 넣으면 재시도.
- 감시 폴더 파일이 안 들어온다: 최대 약 1분 기다린다. 방금 저장한 파일은 3초 이상 지나야 복사된다. `-Check` 로 폴더 읽기 가능 여부를 본다.
- 한글 경로/파일명: 개발 PC(Windows 11, 한글 이름)에서 처리 확인. [검증]

## 9. 이 문서의 검증 범위
검증: 단위/통합 테스트 + 개발 PC(Windows 11, Python 3.14)에서 가짜 OpenAI 호환 서버로 `--check`, 실행, 토큰 교환, 감시 폴더 복사->처리->질문->출처 인용 확인.
미검증: 실제 LM Studio·Gauss 연결, 실사용 PC의 GPU/CPU 속도, waitress 서버(`WIKI_SERVER=waitress` 는 개인 모드에서 사용하지 않음), 실제 브라우저 화면 조작, 디스크 암호화, 다중 Windows 사용자 환경.
