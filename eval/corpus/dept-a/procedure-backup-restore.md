# 백업 및 복구 절차서

- 문서번호: OPS-PRC-004
- 제정일: 2025-02-01
- 최종 개정일: 2025-11-10 (개정 1판)
- 관리부서: 인프라팀 / 담당 박도윤

## 1. 목적
데이터 손실에 대비하여 정기적으로 백업하고 장애 시 신속하게 복구하기 위한 기준을 정한다.

## 2. 백업 대상과 주기
- 운영 데이터베이스(해든DB): 매일 새벽 01:00 전체 백업, 아카이브 로그는 1시간마다
- 파일서버: 매일 새벽 02:00 증분 백업
- 설정 파일(네트워크 장비, 방화벽): 변경 시마다 즉시 백업

## 3. 백업 보관 주기
| 구분 | 보관 기간 |
|---|---|
| 일간 백업 | 14일 |
| 주간 백업 | 8주 |
| 월간 백업 | 12개월 |

백업본은 운영 센터 외에 부산센터의 nas-bk-03에 복제본을 보관한다.

## 4. 복구 목표
- 복구 목표 시간(RTO): 4시간
- 복구 시점 목표(RPO): 24시간
- 핵심 시스템(가온ERP, 그룹웨어)은 RTO를 우선 적용한다.

## 5. 복구 테스트
- 분기 1회 무작위로 선정한 시스템에 대해 복구 테스트를 수행한다.
- 테스트 결과는 복구 성공 여부, 소요 시간, 개선 사항을 문서로 남긴다.
- 복구 테스트에서 데이터 정합성 확인은 업무 부서의 담당자가 참여한다.

## 5-1. 복구 요청 절차
업무 부서에서 데이터 복구 요청서를 제출하면 팀장 승인 후 담당자가 복구한다. 긴급한 경우 구두 승인 후 사후 서면 보완이 가능하다.

| 2025-02-01 | 최초 제정 |
| 2025-11-10 | 복구 테스트 주기를 반기에서 분기로 변경 |
